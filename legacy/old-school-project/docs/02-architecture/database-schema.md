# Database Schema Documentation

This document describes the complete database schema for LearnDash, including all tables, relationships, indexes, and constraints.

## 📊 Overview

LearnDash uses PostgreSQL through Supabase with the following main entities:
- **Users** - Authentication and profile management
- **Quiz Sessions** - Quiz attempt tracking
- **Quiz Questions** - Generated quiz questions
- **Quiz Answers** - User responses
- **Performance Statistics** - Aggregated user data

## 🗃️ Table Definitions

### 1. `quiz_sessions`

Stores metadata about each quiz attempt.

```sql
CREATE TABLE quiz_sessions (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  subject TEXT NOT NULL,
  chapters TEXT[] NOT NULL,
  difficulty TEXT NOT NULL CHECK (difficulty IN ('easy', 'medium', 'hard')),
  question_count INTEGER NOT NULL,
  started_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  completed_at TIMESTAMP WITH TIME ZONE,
  time_taken INTEGER DEFAULT 0, -- seconds
  total_questions INTEGER DEFAULT 0,
  correct_answers INTEGER DEFAULT 0,
  score_percentage DECIMAL(5,2),
  status TEXT NOT NULL DEFAULT 'in_progress' CHECK (status IN ('in_progress', 'completed', 'abandoned')),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique session identifier |
| `user_id` | UUID | Reference to auth.users table |
| `subject` | TEXT | Quiz subject (e.g., "Mathematics") |
| `chapters` | TEXT[] | Array of chapter names |
| `difficulty` | TEXT | 'easy', 'medium', or 'hard' |
| `question_count` | INTEGER | Number of questions in quiz |
| `started_at` | TIMESTAMPTZ | When quiz was started |
| `completed_at` | TIMESTAMPTZ | When quiz was completed |
| `time_taken` | INTEGER | Total time in seconds |
| `total_questions` | INTEGER | Actual number of questions |
| `correct_answers` | INTEGER | Number of correct answers |
| `score_percentage` | DECIMAL(5,2) | Final score as percentage |
| `status` | TEXT | Current quiz status |

#### Relationships
- `user_id` → `auth.users.id` (Many-to-One)
- One `quiz_sessions` → Many `quiz_questions`
- One `quiz_sessions` → Many `quiz_answers`

---

### 2. `quiz_questions`

Stores individual quiz questions generated by AI.

```sql
CREATE TABLE quiz_questions (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  session_id UUID REFERENCES quiz_sessions(id) ON DELETE CASCADE,
  question_text TEXT NOT NULL,
  options JSONB NOT NULL,
  correct_answer INTEGER NOT NULL CHECK (correct_answer >= 0 AND correct_answer <= 3),
  explanation TEXT,
  subject TEXT NOT NULL,
  chapter TEXT NOT NULL,
  difficulty TEXT NOT NULL CHECK (difficulty IN ('easy', 'medium', 'hard')),
  question_hash TEXT NOT NULL,
  question_index INTEGER NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique question identifier |
| `session_id` | UUID | Reference to quiz session |
| `question_text` | TEXT | The actual question |
| `options` | JSONB | Array of 4 answer options |
| `correct_answer` | INTEGER | Index of correct option (0-3) |
| `explanation` | TEXT | Explanation for the answer |
| `subject` | TEXT | Question subject |
| `chapter` | TEXT | Question chapter |
| `difficulty` | TEXT | Question difficulty |
| `question_hash` | TEXT | MD5 hash for deduplication |
| `question_index` | INTEGER | Order in the quiz |
| `created_at` | TIMESTAMPTZ | When question was created |

#### JSONB Structure for `options`
```json
["Option A text", "Option B text", "Option C text", "Option D text"]
```

#### Relationships
- `session_id` → `quiz_sessions.id` (Many-to-One)
- One `quiz_questions` → One `quiz_answers`

---

### 3. `quiz_answers`

Stores user's answers to quiz questions.

```sql
CREATE TABLE quiz_answers (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  session_id UUID REFERENCES quiz_sessions(id) ON DELETE CASCADE,
  question_id UUID REFERENCES quiz_questions(id) ON DELETE CASCADE,
  selected_option INTEGER NOT NULL CHECK (selected_option >= 0 AND selected_option <= 3),
  is_correct BOOLEAN NOT NULL,
  time_taken INTEGER DEFAULT 0,
  answered_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(session_id, question_id)
);
```

#### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique answer identifier |
| `session_id` | UUID | Reference to quiz session |
| `question_id` | UUID | Reference to question |
| `selected_option` | INTEGER | User's chosen option (0-3) |
| `is_correct` | BOOLEAN | Whether answer was correct |
| `time_taken` | INTEGER | Time spent on question (seconds) |
| `answered_at` | TIMESTAMPTZ | When answer was submitted |

#### Relationships
- `session_id` → `quiz_sessions.id` (Many-to-One)
- `question_id` → `quiz_questions.id` (Many-to-One)

### 4. `user_subject_stats`

Aggregated performance metrics per subject.

```sql
CREATE TABLE user_subject_stats (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  subject TEXT NOT NULL,
  total_quizzes INTEGER DEFAULT 0,
  total_questions INTEGER DEFAULT 0,
  correct_answers INTEGER DEFAULT 0,
  average_score DECIMAL(5,2) DEFAULT 0,
  best_score DECIMAL(5,2) DEFAULT 0,
  recent_attempts INTEGER DEFAULT 0,
  last_quiz_date TIMESTAMP WITH TIME ZONE,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  UNIQUE(user_id, subject)
);
```

#### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique stat identifier |
| `user_id` | UUID | Reference to user |
| `subject` | TEXT | Subject name |
| `total_quizzes` | INTEGER | Total quizzes taken |
| `total_questions` | INTEGER | Total questions attempted |
| `correct_answers` | INTEGER | Total correct answers |
| `average_score` | DECIMAL(5,2) | Average percentage score |
| `best_score` | DECIMAL(5,2) | Highest score achieved |
| `recent_attempts` | INTEGER | Quizzes in last 30 days |
| `last_quiz_date` | TIMESTAMPTZ | Last quiz date |

```sql
CREATE TABLE user_chapter_stats (
```

#### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique stat identifier |
| `user_id` | UUID | Reference to user |
| `subject` | TEXT | Subject name |
| `chapter` | TEXT | Chapter name |

| `correct_answers` | INTEGER | Correct answers |

### 6. `quiz_templates`

Pre-defined quiz configurations for quick access.

```sql
CREATE TABLE quiz_templates (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  name TEXT NOT NULL,
  subject TEXT NOT NULL,
  chapters TEXT[] NOT NULL,
  difficulty TEXT NOT NULL CHECK (difficulty IN ('easy', 'medium', 'hard')),
  question_count INTEGER NOT NULL,
  is_public BOOLEAN DEFAULT FALSE,
  created_by UUID REFERENCES auth.users(id) ON DELETE SET NULL,
  usage_count INTEGER DEFAULT 0,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
  updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

#### Fields Description

| Field | Type | Description |
|-------|------|-------------|
| `id` | UUID | Unique template identifier |
| `name` | TEXT | Template display name |
| `subject` | TEXT | Quiz subject |
| `chapters` | TEXT[] | Array of chapters |
| `difficulty` | TEXT | Quiz difficulty |
| `question_count` | INTEGER | Number of questions |
| `is_public` | BOOLEAN | Whether template is public |
| `created_by` | UUID | Creator user ID |
| `usage_count` | INTEGER | Times template used |

## 🔒 Security Policies

### Row Level Security (RLS)

All tables have RLS policies to ensure users can only access their own data:

```sql
-- Example RLS policy for quiz_sessions
CREATE POLICY "Users can view their own quiz sessions" ON quiz_sessions
    FOR SELECT USING (auth.uid() = user_id);

CREATE POLICY "Users can insert their own quiz sessions" ON quiz_sessions
    FOR INSERT WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can update their own quiz sessions" ON quiz_sessions
    FOR UPDATE USING (auth.uid() = user_id);
```

## 📊 Views and Functions

### Helper Functions

1. **`update_user_subject_stats()`**
   - Updates subject-level statistics after quiz completion
   - Calculates moving averages
   - Tracks best scores and recent activity

2. **`update_user_chapter_stats()`**
   - Updates chapter-level statistics
   - Identifies weak areas (accuracy < 60%)
   - Tracks last review date

3. **`complete_quiz_session()`**
   - Marks quiz as completed
   - Calculates final score
   - Triggers all statistics updates

4. **`generate_question_hash()`**
   - Creates MD5 hash for question deduplication
   - Prevents duplicate questions in database

### Useful Queries

#### Get User's Quiz History
```sql
SELECT
  qs.id,
  qs.subject,
  qs.difficulty,
  qs.score_percentage,
  qs.completed_at,
  qs.time_taken,
  COUNT(qq.id) as question_count
FROM quiz_sessions qs
LEFT JOIN quiz_questions qq ON qq.session_id = qs.id
WHERE qs.user_id = auth.uid()
  AND qs.status = 'completed'
ORDER BY qs.completed_at DESC;
```

#### Get User's Performance by Subject
```sql
SELECT
  subject,
  total_quizzes,
  average_score,
  best_score,
  recent_attempts
FROM user_subject_stats
WHERE user_id = auth.uid()
ORDER BY average_score DESC;
```

#### Identify Weak Areas
```sql
SELECT
  subject,
  chapter,
  accuracy_rate,
  total_questions
FROM user_chapter_stats
WHERE user_id = auth.uid()
  AND weak_area = true
ORDER BY accuracy_rate ASC;
```

```sql
ALTER TABLE quiz_sessions ADD COLUMN IF NOT EXISTS time_taken INTEGER DEFAULT 0;
ALTER TABLE quiz_answers ADD COLUMN IF NOT EXISTS time_taken INTEGER DEFAULT 0;

-- Update existing records
UPDATE quiz_sessions SET time_taken = 1800 WHERE time_taken = 0;

-- Create new indexes for performance
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_quiz_sessions_time_taken
  ON quiz_sessions(time_taken);
```

## 📈 Performance Considerations

### Optimization Tips

1. **Use `EXPLAIN ANALYZE`** for slow queries
2. **Batch operations** for bulk inserts/updates
3. **Connection pooling** with Supabase
4. **Materialized views** for complex reporting
5. **Partitioning** for large tables (future)

### Query Optimization

```sql
-- Instead of this:
SELECT * FROM quiz_sessions WHERE user_id = 'uuid';

-- Use this:
SELECT id, subject, score_percentage, completed_at
FROM quiz_sessions
WHERE user_id = 'uuid'
  AND status = 'completed'
ORDER BY completed_at DESC
LIMIT 10;
```

## 🔧 Database Maintenance

### Regular Tasks

1. **Weekly**: Analyze slow queries
2. **Monthly**: Update statistics (`ANALYZE`)
3. **Quarterly**: Review and optimize indexes
4. **As needed**: Archive old data

### Cleanup Scripts

```sql
-- Archive old quiz sessions (older than 1 year)
CREATE TABLE quiz_sessions_archive AS
SELECT * FROM quiz_sessions
WHERE completed_at < NOW() - INTERVAL '1 year';

DELETE FROM quiz_sessions
WHERE completed_at < NOW() - INTERVAL '1 year';
```
